01 输入关注点用一句话说出你关注什么，价格、热度、事件或日历条件。例如「茅台跌破 1400 提醒我」。
02 检查并确认系统生成规则草案，你可以修改类型、标的、阈值和频率
03 查看结果每次检查都会说明触发、未触发、降级或未执行的原因
  • 草案不会自动执行：点击「确认并创建任务」，规则才会入库并按间隔开始检查。

  • 每条检查记录都可审计：保留判定依据、数据时点、数据来源与执行状态。

状态口径：「待检查」 → 「已触发 / 未触发 / 冷却中 / 已去重 / 已降级 / 检查失败 / 数据受限 / 数据存在冲突 / 未执行」。

去重与冷却：同一任务、同一规则版本、同一交易日且条件持续成立时，只提醒一次。冷却期内记为「冷却中」，冷却结束后同一天记为「已去重」；条件解除或进入下一交易日可重新触发。

组合条件（AND / OR）：用「并且 / 且 / 同时 / and」或「或者 / 或 / or」连接多个子条件，即可创建组合规则。判定时每个子条件独立求值，再按逻辑合并：AND 需要全部满足，OR 只需一个满足。任一子条件数据不可用或数据时点不可确认时，整体记为已降级且不强行判定。后写的子条件可以省略标的，会自动继承前一个子条件的标的。同一条规则暂不支持混用 AND 与 OR。

任务归档：任务可以暂停（保留在列表、随时恢复）或归档（收进归档区、不再调度）。归档不删除任何东西——版本历史、检查记录、判定证据全部保留，随时可以「恢复启用」。本产品不提供永久删除。

参数边界：检查间隔 1–1440 分钟；冷却 0–10080 分钟；热榜名次 1–100；事件关键词 1–20 字符。

指标口径说明

Q1：数据从哪来？

全部来自扶摇金融数据 API（当前 source=fuyao）。每条记录保留 request_id，可回溯到原始调用。

Q2：每条记录你能看到什么？

  • 来源（source）
  • 字段（价格类 priceField=last_price；热度类 rank / heat）
  • 值（如 1258.62）
  • 单位（unit，如 CNY/share）
  • 数据时点（as_of，并标注取法 as_of_source）
  • 口径（sessionLabel，如「非交易时段，价格口径为最近交易日收盘附近快照」）
  • 请求编号（request_id）

Q3：不同条件的数据时点怎么取？

条件接口 / 数据集关键字段as_of 取法
价格prices/snapshot
+ prices/historical		last_price（元/股）日线最后一根 K 线日期（kline_date）

日历calendar/trading-daysdate当日（trading_calendar）

为什么不用接口 timestamp 当行情时点：实测该字段是抓取时刻而非行情时点，直接当作行情时间会误导判断。因此价格类的数据时点一律取日线日期，界面单独标注 marketDate。

热度数据时点（三态）：① 数据源提供榜单业务时点 → 判定并写明是哪个时点的榜单；② 只有本次获取时间（当前真实情形）→ 仍给判定，但必须同时写明「榜单业务时间：数据源未提供」与可信度提示；③ 两者都拿不到 → 记为数据受限（DATA_RESTRICTED），声明本次未执行条件判断，绝不出「未触发」。

Q4：数据出问题怎么办？

降级口径：DATA_STALE 日线最后日期落后于最近应完成交易日（盘中按上一交易日、收盘后按最近交易日）；DATA_NOT_READY 榜单或异动列表返回空。数据不可用时一律记为「已降级 / 检查失败」，绝不折算为「未触发」。

数据冲突（多源业务时点不一致）：价格条件同时依赖两份数据——实时快照（last_price）与历史日线（最新收盘 close）。两份数据的业务时点必须能归入同一条时间线（盘中：快照 = 今日盘中、日线 = 上一交易日；非盘中：两者同为最近收盘日）。一旦归不进同一条时间线，系统不挑其中一份顺手的来用，而是记为「数据存在冲突」（DATA_CONFLICT）并声明本次未执行判定——挑一份用等于拿一半的数据编一个完整结论。判据是时点不自洽，不是数值不一致：盘中快照 1398 元、昨收 1412 元完全正常，把数值差异当冲突会让系统天天报警。

复现用的演示场景：快照业务时点 2026-09-29 14:55（价格 1398.00 元）、日线最新收盘 2026-09-30（收盘 1412.00 元），两份数据所属时点不同 → 状态「数据存在冲突」、结果「本次未执行条件判断」、原因「实时快照与日线数据所属时点不同」、建议「等待下一次检查或手动重试」。该场景由 test/conflict.test.js 固化为可重复执行的用例。

非交易日：价格 / 热度 / 事件类记「未执行」，不计为失败；日历类正常判定；组合条件只要含盘中数据子条件，同样按非交易日跳过。

口径边界（如实说明）

以下两项已预留状态码，当前版本尚未实际触发：

  • 盘中数据无更新（DATA_STATIC）：未在真实盘中验证。
  • 数据格式异常（SCHEMA_MISMATCH）：当前用「字段缺失」（FIELD_MISSING）口径代替。

DATA_RESTRICTED（数据受限）与热度三态中的「有榜单业务时点」分支已实现并有单元测试覆盖，但当前数据源不提供榜单业务时点，因此线上真实运行固定落在第 ② 种（只有获取时间）。第 ③ 种是有意保留的防御分支。
